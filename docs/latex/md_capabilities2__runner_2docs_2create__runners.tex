 The runner API is designed to be extensible, so that specific runners can be created on a per provider basis. Another feature that can be implemented is cross-\/runner communication, which could allow capabilities to be combined at runtime to perform more complex tasks. This could overcome limitations in robot programming in which there is a common need for extensive pre-\/definition of tasks.\hypertarget{md_capabilities2__runner_2docs_2create__runners_autotoc_md19}{}\doxysection{\texorpdfstring{Inheritance}{Inheritance}}\label{md_capabilities2__runner_2docs_2create__runners_autotoc_md19}
A runner is a plugin that inherits from the {\ttfamily \doxylink{classcapabilities2__runner_1_1RunnerBase}{capabilities2\+\_\+runner\+::\+Runner\+Base}} class. The {\ttfamily Runner\+Base} class is a pure virtual class that defines the interface for a runner. The {\ttfamily Runner\+Base} class has the following methods\+:


\begin{DoxyEnumerate}
\item {\ttfamily start} -\/ starts the runner
\end{DoxyEnumerate}
\begin{DoxyEnumerate}
\item {\ttfamily stop} -\/ stops the runner
\end{DoxyEnumerate}
\begin{DoxyEnumerate}
\item {\ttfamily trigger} -\/ triggers the runner
\end{DoxyEnumerate}

Multiple classes are provided to inherit from, depending on the type of runner you want to create. A notable example is the {\ttfamily \doxylink{classcapabilities2__runner_1_1ActionRunner}{capabilities2\+\_\+runner\+::\+Action\+Runner}} class, which is used to create runners that run actions.\hypertarget{md_capabilities2__runner_2docs_2create__runners_autotoc_md20}{}\doxysection{\texorpdfstring{Export with Pluginlib}{Export with Pluginlib}}\label{md_capabilities2__runner_2docs_2create__runners_autotoc_md20}
The runner should be exported as a plugin using the {\ttfamily PLUGINLIB\+\_\+\+EXPORT\+\_\+\+CLASS} macro.
